#+title: myweb

Author, build and deploy my web sites from a datalad dataset of org sources
(~~/keep/web~).  See [[file:proposal.md]] and [[file:decisions.md]] for the
design.

* Site layout

#+begin_example
~/keep/web/
  myweb.toml              taxa and targets, travels with the dataset
  config/_default/        hugo config common to all targets
  config/<environment>/   per target hugo config (baseURL, ...)
  archetypes/<taxon>.org  templates for "myweb new" ($title, $date, $slug, ...)
  themes/plain/           the theme, plain HTML, no JavaScript
  content/<taxon>/<slug>/ one item, a Hugo leaf bundle:
      <slug>.org            source, for taxa rendered by ox-hugo
      index.md              exported by ox-hugo, committed
      index.org             source, for taxa rendered by hugo (notes)
      version.txt           version stamp, see "myweb version"
      *.svg, *.png, ...     resources, linked relatively
#+end_example

Item metadata is in org keywords: ~#+title~, ~#+date~, ~#+hugo_tags~ (or
~#+tags[]~), ~#+hugo_draft~ (or ~#+draft~), and:

- ~#+audience:~ personal | work | both :: which targets get the item
- ~#+visibility:~ public | unlisted | protected :: unlisted and protected
  items are built but never listed (indices, RSS, sitemap) and carry
  ~noindex~.  Protected items get an ~.htaccess~ and only go to targets with
  ~auth = true~.

Hugo can not filter on front matter so myweb writes an extra hugo config
per build: content mount exclusions and cascades by path.

Every headline gets a ~CUSTOM_ID~ property, a slug of its heading
(~myweb ids~, and ~publish~ does it too).  Org's generated ~org1234abc~
ids are replaced, others kept.  The id is the section's HTML anchor and
the theme puts a ~#~ link to it after each heading.

Each page's org source, less ~:noexport:~ and ~COMMENT~ subtrees, is
published beside it as ~<slug>.org~ and the theme links it ("org source",
from the ~source~ param myweb cascades).  A top ~.htaccess~ serves ~.org~
as the target's ~org_type~ (default ~text/plain; charset=utf-8~, needs
~AllowOverride FileInfo~; set ~org_type = ""~ to omit it).

* Search and access realms

Site search runs in the reader's browser over static JSON indexes that
~myweb build~ writes after hugo, so a reader can search exactly what the
web server lets them fetch.  There is no server side to trust.

Every page is in one access realm: ~public~, or for a protected page the
realm its ~#+access:~ names (default ~protected~) from the target's
~realms~, each an Apache ~Require~:

#+begin_src toml
[target.work.realms]
protected = "valid-user"       # the default when none are given
dune = "user alice bob"        # eg a collaboration's talks
#+end_src

A page whose realm the target lacks is not built for it.  One function
(~access.htaccess~) writes the ~.htaccess~ for both a realm's pages and its
index, so they always admit the same readers, and all use ~AuthName~ = the
realm so one login covers the realm.

- ~search/index.json~ :: public pages only
- ~search/<realm>/~ :: the realm's ~.htaccess~, its ~index.json~, and a copy
  of the search page that loads the public and the realm's index
- unlisted pages :: in no index

No index holds two realms, so a reader of ~dune~ learns nothing of
~protected~ and vice versa; one with both searches each.  The build fails
if any index holds a page of another realm or a realm index is not guarded
like its pages.  The public search page links each realm's search, so
realm names are public.  Unlisted and protected pages were already kept
out of lists, RSS and the sitemap.

Without JavaScript the search page offers the section indices instead.

* Commands

#+begin_example
myweb new posts "A Title" -t tag -d 2026-12-31   # draft, TODO in org-agenda
myweb new notes "TIL" -m "One-liner note."
myweb edit <item>       # Emacs + background "hugo server" with drafts + browser
myweb status [-a]       # drafts: deadline, TODO, words, figures, ...
myweb export [<item>]   # ox-hugo export of stale items
myweb ids <item>|-a [-n] [--commit]  # slug CUSTOM_ID for every headline
myweb check <item>      # export, build to a check stage, link check; .check.txt
myweb publish <item>    # undraft, export, save, stamp, tag, build, deploy
myweb build [target]    # build to stage, .htaccess, verify, rsync to dest [and remote]
myweb version [-u]      # show/update version.txt stamps
myweb search ...        # passes to the configured search (orgface search)
myweb setup systemd|cron|git [-T target] [--print]
#+end_example

* Version stamps

A ~version.txt~ holds ~git describe~ of the last commit that touched what it
covers, plus the commit hash.  All ~version.txt~ files are excluded from what
any stamp covers, so committing stamps does not change them: a stamp changes
iff its content does.  ~publish~ commits content, then stamps, then commits
the stamps.

* Configuration

~~/.config/myweb/config.toml~ holds host specifics (site path, hugo and
Emacs commands) and may override any ~[taxon.X]~ or ~[target.X]~ field of the
site's ~myweb.toml~.  ~MYWEB_SITE~, ~MYWEB_HUGO~ and ~MYWEB_CONFIG~ override.

Load ~src/myweb/myweb.el~ in Emacs so interactive ox-hugo exports (eg
~org-hugo-auto-export-mode~) keep bundle links relative, as ~myweb export~
does.  ~myweb edit~ loads it for you.
